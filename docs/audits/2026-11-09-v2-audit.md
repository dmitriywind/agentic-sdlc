# v2 audit and decisions (2026-11-09)

Four read-only audits of commit `c990302`: best practices for Q4 2026, the Claude setup ("doctor"),
ambiguity and step folding, and a project-lead review. This file records the decisions and the
interface changes that follow from them. `references/architecture.md` is updated to match; after
that, the contract wins over this file.

## Verdicts

| Audit | Verdict |
|---|---|
| Best practices | Process model aligned. Security and operability are gaps that block adoption as critical infrastructure. |
| Claude doctor | Design sound. Three first-run failures: headless runs get no tool permissions, the AGENTS.md pointer is not loaded when CLAUDE.md exists, the Managed Agents deployment JSON has wrong shapes. |
| Fold and cleanup | Fold `bench` into the CLI; thin `judge-run`; keep `verify-ux` (narrowed) and `improve-factory`. The learning loop cannot complete today. Several rules disagree. |
| Project lead | Approve with changes: doc errors, release hygiene, no migration note, alpha status not stated. |

## Decisions (by the project owner)

1. **Approval.** A product CR in the Full lane needs one human approval as well as the agent
   review. A Fast-lane CR merges on the agent review. A `guardrail` factory CR needs the factory
   owner's approval. Binding key `forge.human_approval: full-lane | always | never`, default
   `full-lane`.
2. **Folding.** Delete the `bench` skill; `improve-factory` calls the `bench` CLI. `judge-run`
   keeps only the LLM grading; picking scorers, hard-fact caps, human grades and recording move
   into `ledger` code. `verify-ux` and `improve-factory` stay, narrowed.
3. **Scope.** v2 is Git only. Delete the Mercurial, Perforce and Helix Swarm adapters, hooks and
   docs. Forges: GitHub, GitLab, Azure DevOps, Bitbucket.
4. **Claude packaging.** Ship a Claude Code plugin (skills, hooks, MCP server). `init --harness
   claude` no longer copies `.claude/skills`; it generates tier subagents and an `@AGENTS.md`
   import. Codex, Cursor and Antigravity keep reading `.agents/skills`.

## Interface changes

### Gates and checks

| Change | Detail |
|---|---|
| `Required` comes from CI | A CI job named `Required` on `pull_request` (no secrets) runs `commands.install` and `commands.verify`. No agent posts it. The ruleset notes `integration_id` pinning; `doctor` warns when a required check is not pinned. |
| New gate `proofs-on-base --cr <n>` | Same no-secrets job: runs the CR's new or changed proof files against the merge base's product code; posts status `proofs-on-base` (success when each new proof fails on base). Replaces review-pr's local run. |
| New gate `approval --cr <n>` | Replaces `factory-class`. Computes the class: `product-fast`, `product-full`, `tuning`, `guardrail`. Posts status `human-approval`: success for `product-fast`; for `tuning` when `tuning` is in `learning.auto_merge_classes`; for `product-full` (when `forge.human_approval` is `full-lane` or `always`) and for every product CR when `always`, only with an approving review on the head SHA by a human (not in `owners.bots`, not `forge.review_identity`); for `guardrail` only with an approval by `owners.factory`. Runs on CR events and on review submitted. |
| Classification | Any change to skill text is `guardrail`. `tuning` is only: the `models` map, and a skill's `metadata.tier` when that skill has a bench suite. Everything else under `paths.factory` is `guardrail`. |
| Forge verb `approvals <n>` | `{ user, state, sha }[]` for the CR's reviews. |
| Required checks | `ticket-linkage`, `Required`, `proofs-on-base`, `review`, `human-approval`, `skill-regression`. `factory-owner` is removed. |
| CODEOWNERS | Removed from templates; `require_code_owner_review` off. The `approval` gate enforces owner approval by class, so `tuning` can auto-merge. |

### Review runtime

`review-pr` never runs CR code. It reads `Required` and `proofs-on-base` from CI. The review job
holds the review token and runs no install or test command.

### CLI and MCP

| Change | Detail |
|---|---|
| `dispatch` | `--ticket` or `--cr` (a factory CR has no ticket). Idempotency key `<ticket or cr>-<skill>-<head sha>`: a second dispatch with the same key inside `stall_minutes` prints `{ skipped: true }`. |
| `ledger plan --run <id>` | Applicable scorers, the evidence refs (trace, CR, diff) and the hard-fact cap for one run. |
| `ledger record --run <id> --file <scores.json>` | Validates scorer names and scales, applies caps, posts one `<!-- scores -->` comment on the heartbeat ticket. `readRuns` reads these. Human grades stay comments by owners. |
| `ledger summary` | Adds `learning: { due, cyclesSince, spentWeekUsd }` computed from heartbeats and run rows, so no skill writes a counter. |
| `ledger stale --max-hours <h>` | Exit 1 when the newest heartbeat is older; for a dead-man job. |
| `board comments --trusted` | Shorthand for `--author` with `owners.bots`, `owners.product`, `owners.factory`. |
| `bench compare` | Needs at least `learning.bench_min_cases` (default 20) shared cases and `learning.bench_trials` (default 3) trials per case; uses the Wilson lower bound of the pass rate. Fewer is `regressed`. |
| HTTP | Retry with backoff on 429 and 5xx (3 tries, honour `Retry-After`). |
| MCP | Default tool list excludes `forge_approve` and `forge_status`; `mcp --allow approve,status` adds them. `vcs_tag` removed. |
| Removed | `vcs` adapters `hg`, `p4`; forge `swarm`; `product.kind`; `board.milestone`; scorer `tier`; duplicate `shippedOptions`. |

### Binding

New: `forge.human_approval`, `commands.preview` (optional: deploys a CR head for `verify-ux`),
`learning.bench_min_cases`, `learning.bench_trials`. Template default
`learning.auto_merge_classes: []` until a bench baseline exists. Skill frontmatter: `tier` moves to
`metadata: { tier }`.

### Templates

- Claude headless runs: `--permission-mode acceptEdits`, `--allowedTools` for the CLI, git push
  and the MCP server, `--max-turns`; the cycle job adds `--disallowedTools` for `forge approve`.
  Prompts start with `/agentic-sdlc:sdlc`. A guard step fails the individual profile when
  `ANTHROPIC_API_KEY` is set.
- Review runs after the cycle finishes (job dependency), never on its own clock.
- Pinned installs: the project's `agentic-sdlc` devDependency through `npm ci`; actions carry a
  `# pin to a commit SHA` note.
- Managed Agents deployment JSON uses the documented `content` array and `budget` object.
- `merge_group` trigger on the CR workflow, for merge queues.
- A dead-man job runs `ledger stale`.

### Docs and hygiene

Alpha banner, `@next` install, what `init` writes, a try-it-locally path, a v1 migration note,
CHANGELOG, SECURITY, CONTRIBUTING, package metadata. Contract: one home per rule, the stale
binding YAML replaced by a pointer to `templates/binding.yml`, no WalletMate references. This repo
does not run its own factory yet; README says so.

## Deferred

Feature-flag proof kind and an executed rollback; append-only run ledger in `traces.uri` with
attestation; OpenTelemetry spans; short-lived App/OIDC tokens; per-executor egress allowlists;
an event-triggered cycle for P0. Each is a follow-up, not part of this change.

## Superseded after the audit (reconciled 2026-11-10)

The contract wins over the text above. These later decisions change it:

- **No npm.** The npm name `agentic-sdlc` is another project. The CLI and plugin ship from Git:
  `npm i -D --allow-git=root github:dmitriywind/agentic-sdlc#v<version>`, then `npx --no agentic-sdlc`.
  `dist/` is committed, and a release is a `v<version>` tag. So the "`@next` install" and the
  pinned devDependency above mean the `github:` spec. `init` writes `allow-git=root` to `.npmrc` (npm 12).
- **Classification.** A CR that mixes product and factory paths is `guardrail`. A product CR that
  touches `paths.lane_areas` is `product-full`, whatever the ticket's lane.
- **Status token.** `forge status` posts with `review_token_env`; only the `proofs-on-base` gate
  uses `token_env` (`{ as: 'ci' }`). Azure DevOps posts PR iteration statuses.
- **`proofs-on-base`** runs in its own no-secrets job, not in the `Required` job. Where it cannot
  post the status, the job result is the check (Azure: the PR build).
- **Review runtime** allows only the CLI and the MCP server: no git writes, no npm.
- **HTTP retry** skips a 5xx on POST, since the write may have happened.
- **Trunk-based** applies to this repo too: work lands on `master` (renamed from `main` on 2026-11-11); no long-lived branch.
